openloops.receiver_tick#

One tick of the board-receiver job: check for work without a model, then hand over.

ADR-011. A launchd StartInterval job runs this every few minutes. Starting a Claude session on every tick would cost money while nothing is pending, so the tick first asks the board store, with plain HTTP and no model, whether anything needs the receiver. Only if something does (or the question cannot be answered) does it replace itself with the real command, claude -p <the receiver prompt>.

Liveness. Every successful check writes the board’s meta/receiver heartbeat (the receiver’s own document, under the session name from board/board.json), so an idle board stays green and a dead job turns it amber after 20 minutes. It also touches a local board-receiver.lastcheck stamp, which ol receiver-job-status reports as “last check”, separately from “last work” (the log, written only by ticks with work).

Fail closed on configuration, open on anything else. A configuration error (no credentials file, a missing key, a cleartext origin, a refused sign-in, a 403 from the store) cannot be fixed by a session, so the tick starts none and says so in the log on every tick; the stale heartbeat turns the board amber. Any other failure (the store down, a malformed answer, a bug here) starts the session anyway, because a check that silently suppressed the receiver would be the failure this package exists to prevent. Repeated failures back off exponentially: one hour, then two, four, capped at six.

This is the one module that talks to the network, to the owner’s own board store (the HTTP API of ADR-009). Nothing imports it; import openloops never loads it.

The work set is the one references/receiver.md defines: events with no receipt, processing receipts older than 15 minutes, and queued receipts and failed receipts marked transient. Those last two are retried only once they are an hour old (RETRY_AFTER): a receipt that waits on another machine, a busy worker or a lasting GitHub error would otherwise start a paid session every tick, all day, to change nothing. The sign-in is the one in references/receiver-http.md.

openloops.receiver_tick.check(env_file=PosixPath('~/.config/openloops/board-receiver.env'), *, heartbeat_by=None, now=None)[source]#

Ask the store whether anything needs the receiver. Raises if it cannot ask: ConfigError when no session could fix it, anything else otherwise.

With heartbeat_by (the board’s session name) it also writes the meta/receiver heartbeat, and says what happened in the result’s heartbeat. A failed heartbeat never fails the check: the board turning amber is how that shows.

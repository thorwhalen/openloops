openloops.pile#

The pile: GTD’s In list, kept as GitHub issues in a private repo, and its clarify step.

A capture (an Apple Shortcut, the gh CLI, anything that can send a request to the issues API) is one open issue labelled pile in the owner’s pile repo. This module is the one place that reads and changes that pile, so the agent skill (openloops-pile), the ol pile-* commands and a voice surface (bosun) all do the same thing:

  • items() / show(): what is on the pile, read-only;

  • propose(): a first proposal per item, from a model-free heuristic by default (proposer= is the seam an agent’s own reading replaces);

  • plan(): the steps that carry out one decision the owner said yes to (a loop, an idea, an issue in another repo, work handed to a session, done, dropped), ending with a signed comment on the pile item saying where it went. **openloops never writes to GitHub** (ADR-008, ADR-014): the caller runs the steps with its own tools;

  • signed(): a signed progress note, for a session working on an item;

  • nudge(): keep one reminder loop pending while items wait too long. It never acts on an item.

Every write is signed (signature()): the agent’s name and, on private repos, a link to its session, so an idea’s development can always be traced back to who did it. Public destinations get no private content: an issue filed in a public repo carries only the text the caller wrote for it, no dictation, no pile link and no session link.

Nothing here runs on capture and nothing acts without being called: no Action, no webhook (the owner’s rule). GitHub is only read, through gh (run_gh=); the one write is nudge()’s reminder loop, through openloops’ own reminder runner.

>>> parse_item({"number": 7, "title": "call about zodal", "body": "call about zodal\n\n— pile: inbox",
...             "labels": [{"name": "pile"}, {"name": "inbox"}], "createdAt": "2026-11-20T10:00:00Z",
...             "url": "https://github.com/o/_pile/issues/7"}).hint
'inbox'

openloops.pile.nudge(*, stale_days=3.0, at='09:00', repo=None, run_gh=None, loops_api=None, now=None)[source]#

Keep one reminder coming while any pile item waits longer than stale_days.

Idempotent; run it from a timer. An item counts while it is on the pile (pile) or handed to a session (working): a session that died leaves it there. When something is stale, no nudge is still to come, and none was made in the last NUDGE_EVERY_HOURS, it closes the nudges that already fired and makes one loop (source pile-nudge) for the next at in the owner’s zone. The push says only the count and the oldest age (it crosses a public relay). When nothing is stale, every open nudge is withdrawn. It never touches a pile item.

openloops.pile.plan(number, kind, *, reading=None, by=None, session=None, title=None, when=None, reveal=False, target_repo=None, issue_body=None, tags=None, reason=None, force=False, repo=None, run_gh=None)[source]#

The steps that carry out one decision the owner said yes to, as data. Changes nothing.

openloops never writes to GitHub (ADR-008, ADR-014): the caller runs the steps in order, with its own tools (gh in a Claude Code session, the connector’s comment and create tools on a voice surface), substituting RESULT in later steps with what the first step produced. reading is the agent’s interpretation, and opens the signed comment. Per kind:

  • loop: remind (ol remind; source = the item’s URL), then close as routed; title is required with reveal (the push crosses a public relay);

  • idea: idea (ideadump add with the dictation verbatim), then close as routed;

  • issue: create_issue in target_repo (title + issue_body required); anything but a private repo of the pile’s owner gets that text only, no pile link and no session link;

  • work: hand-off to a session; labelled working and left open; the session posts signed() notes and finishes with done;

  • done: close as routed, reason = the evidence;

  • drop: close as not planned, reason required (never silent);

  • ask: stays on the pile, labelled needs-owner, reason = the question.

A destination already recorded on the item (a → issue/loop/idea line from an earlier, half-run plan) refuses a second one unless force: finish that plan’s remaining steps instead. The pile itself must be a private repo of its owner.

Step ops: remind, idea, create_issue, comment, labels, close (reason in gh’s spelling, rest_reason in the REST API’s).
